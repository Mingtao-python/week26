# Failure Analysis Report

Source: `logs/failures.jsonl` (5 records), all generated by
`failure_analysis_report.analyze_failure(prompt, context, output)`.

The function returns a structured report with these fields:
`{prompt, context, output, unsupported_claims, fabricated_refs, contradictions, likely_cause, next_experiment}`.

This document follows the **Engineering Assignment Implementation 5 — Failure Analysis Report**:
pick at least three failures, trace each through prompt / context / model-output / application
layers, state the evidence, and propose one controlled follow-up experiment per failure.

Three failures are analysed in depth below: **F1 (relativity URL)**, **F3 (silent abstention)**,
and **F5 (Smith v. Acme)**. F2 and F4 are summarised in §4.

## F1 — Fabricated citation for the theory of relativity

**Claim.** *"The theory of relativity was published by Einstein in 1905 according to http://relativity-facts.net."*

**Evidence.**
- Source evidence does not contain any URL.
- The URL `http://relativity-facts.net` does not appear anywhere in the supplied context.
- `failure_label = "truncated"` and `fabricated_refs = ["http://relativity-facts.net"]` in
  `logs/failures.jsonl`.

**Layer-by-layer trace.**

| Layer         | What happened                                               | Evidence                  |
|---------------|-------------------------------------------------------------|---------------------------|
| Prompt        | Asked for "a citation for the theory of relativity."        | prompt text               |
| Context       | Evidence says only "Einstein published relativity in 1905." | context text              |
| Model output  | Added a plausible-sounding URL not present in context        | output text vs context    |
| Application   | Did not validate that citations are in retrieved evidence    | absence of URL check      |

**Likely cause.** Generation failure: the model augmented a correct factual answer with an
invented URL because the prompt implicitly invited a URL.

**Severity.** HIGH — citation fabrication in any research / legal / academic workflow.

**Follow-up experiment.**
- Hypothesis: adding a citation guard (every URL or case name in the output must be present in
  retrieved evidence) reduces the fabricated-citation rate.
- Method: re-run the H2 / H4 test set with the guard on and off; record failure counts.
- Variable changed: only the guard. All other settings identical.
- Expected outcome: 50 % → ≤ 10 % fabricated citations on the test set.

## F3 — Silent abstention on a "summarise the report" request

**Claim.** Model returned an empty string when asked to summarise an attached quarterly report.

**Evidence.**
- `failure_label = "unknown"` (i.e. `analyze_failure` could not classify the cause).
- `context = ""` — no document was supplied.
- `output = ""` — model returned nothing.

**Layer-by-layer trace.**

| Layer         | What happened                                              | Evidence                  |
|---------------|------------------------------------------------------------|---------------------------|
| Prompt        | User asked for a summary of an attached report.            | prompt text               |
| Context       | No document was actually attached — context is empty.       | empty context             |
| Model output  | Empty string instead of "I don't see the document."        | empty output              |
| Application   | Did not enforce a minimum output length nor an explicit abstention policy. | absence of validation |

**Likely cause.** Policy / application failure: the system has no rule that says "if the
required attachment is missing, ask the user instead of returning empty." Combined with model
behaviour, this becomes a silent failure.

**Severity.** MEDIUM — UX is broken but the user is not misled by false content.

**Follow-up experiment.**
- Hypothesis: requiring the application to insert an explicit "if no document attached → ask"
  prompt template eliminates silent empty answers.
- Method: run 10 cases with the template; record non-empty answer rate.
- Variable changed: only the system prompt template; everything else identical.
- Expected outcome: empty-answer rate 100 % → 0 %.

## F5 — Fabricated legal case citation (Smith v. Acme)

**Claim.** *"In Smith v. Acme (2023), the court ruled that …."*

**Evidence.**
- `fabricated_refs = ["Smith v. Acme (2023)"]`
- `unsupported_claims = ["Smith v. Acme (2023)"]`
- The supplied context explicitly says *"We have no precedent in the supplied evidence."*

**Layer-by-layer trace.**

| Layer         | What happened                                                 | Evidence                         |
|---------------|---------------------------------------------------------------|----------------------------------|
| Prompt        | Asked for a court case supporting an argument.                 | prompt text                      |
| Context       | Context explicitly states no precedent exists.                | context text                     |
| Model output  | Invented a plausible case name + year + ruling.                | output text vs context           |
| Application   | No citation guard (same root cause as F1).                     | absence of URL / case check      |

**Likely cause.** Generation failure, identical mechanism to F1 but higher severity because the
fabrication targets a high-impact domain (legal).

**Severity.** HIGH — fabricated legal citations can mislead clients and create liability.

**Follow-up experiment.**
- Hypothesis: requiring every cited case title to appear in retrieved evidence reduces the
  fabricated-case rate.
- Method: build 10 fabricated-case queries (similar to H4) and run with and without the guard.
- Variable changed: only the guard.
- Expected outcome: fabricated-case rate 100 % → 0 % in the test set; human review still
  required for production.

## What this report does NOT prove

- It only covers **5 hand-picked failures**, not a population sample.
- It cannot tell whether the model's behaviour is consistent across versions.
- It does not separate retrieval failure from generation failure at scale. To do that, record the
  retrieval top-k IDs alongside each failure and inspect whether the right document was returned.
- The next-experiment proposals are hypotheses; they have to be run before they count as evidence.
